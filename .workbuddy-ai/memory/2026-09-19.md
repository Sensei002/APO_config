## Follow-up 2: compression enabled, values measured (not guessed)

User: "now compression. Do it." Enabled ReaComp in the live config.

### The breakthrough: a VST2 host in pure Python

Rather than guessing ReaComp's parameter scale, wrote a minimal VST2 host with
`ctypes` and interrogated the plugin directly. Two reusable scripts now live in
`tools/`:

- `vst_inspect_params.py` — loads a VST2 DLL via `VSTPluginMain`, walks
  `numParams`, and for each parameter prints `getParameterName`, plus
  `getParamDisplay` for a sweep of normalised values. This reveals the real
  mapping of any opaque parameter.
- `vst_measure_gain.py` — calls `processReplacing` on synthetic sine blocks and
  measures output level, i.e. real gain staging without listening.

Key ctypes details that made it work:
- `VSTCALLBACK` is `__cdecl` on Windows → use `ctypes.CDLL`, not `WinDLL`.
- `AEffect` is 192 bytes on x64; `numParams` is at offset 44.
- Must stub the `audioMaster` callback: opcode 1 (version) → 2400, 7 (getTime)
  → pointer to a populated `VstTimeInfo`, 16 → sample rate, 17 → block size,
  21 → 1, 23 → 2, 32/33 → vendor/product string, 34 → 1000, 39 → 1.
- Init sequence: `effOpen(0)`, `effSetSampleRate(10)`, `effSetBlockSize(11)`,
  `effMainsChanged(12, value=1)`.
- ReaComp reports `numInputs=4` (main L/R + sidechain L/R) and `numOutputs=2`.
  Feed the same signal to all 4 inputs when measuring, or the sidechain reads
  silence and nothing compresses.

### ReaComp parameter scale (authoritative, measured)

| Param | Scale |
|---|---|
| Thresh | linear amplitude, displayed as `20*log10(v)`. `0.1` = −20 dBFS |
| Ratio | `ratio = v*100 + 1`. `0.03` = 4:1, `0.05` = 6:1. **`0` = 1:1** |
| Attack | `ms = v*500` |
| Release | `ms = v*5000` |
| Pre-comp | `ms = v*250` |
| Lowpass / Hipass | `Hz = v*20000` |
| Dry / Wet | linear gain, displayed in dB. `0` = −inf, `1` = 0 dB |
| RMS size | `ms = v*1000` |
| Knee | `dB = v*24` |
| AutoMkUp, AutoRel, ClsAttk, PreviewF | toggles, ≥0.5 = on |
| AntiAls | stepped 0–13 |
| SignIn / AudIn | 0–1084 |

**Their original config had `Ratio 0` = 1:1 — the old ReaComp was doing nothing.**

### Measured gain staging of the shipped setting

4:1, 10 ms attack, 150 ms release, 6 dB knee, −20 dBFS threshold, AutoMkUp on:

| Input | Output | Net |
|---|---|---|
| −3 dBFS | −6.0 dBFS | −3.0 dB |
| −12 dBFS | −8.4 dBFS | +3.6 dB |
| −24 dBFS | −16.5 dBFS | +7.5 dB |
| −40 dBFS | −32.5 dBFS | +7.5 dB |

Auto make-up gain is a **fixed +7.5 dB**, and the output tops out around
−6 dBFS — no clipping risk, so the −5 dB preamp was left alone.

Verified independently: for a −12 dBFS peak sine the RMS detector sees
−15 dBFS, 5 dB over threshold, 4:1 → 3.75 dB predicted reduction vs 3.9 dB
measured. The model is sound.

### Resolved

User chose the browser sign-in path. Fixes applied:

- `git config --local credential.helper ""` followed by
  `git config --local --add credential.helper manager`. The empty value **resets
  the accumulated helper list**, which is the only way to stop the system-level
  `helper-selector` from running first. Without the reset, git would have tried
  `helper-selector` and blocked on its console prompt.
- `git config --local credential.https://github.com.provider github`.
- Ran the push **in the background** so Git Credential Manager could open its
  sign-in UI without the shell blocking on it.

Result: `* [new branch] main -> main`, branch tracks `origin/main`.

Independently verified via the GitHub API
(`api.github.com/repos/Sensei002/APO_config/contents/`) — repo root contains
`.workbuddy-ai/`, `FRESH_INSTALL.md`, `README.md`, `backup_config_original.txt`,
`config.txt.bak`, `mic_sm7b_podcast.txt`, `tools/`.

### Reusable lesson

Pushing from this environment needs a credential path decided up front. There is
no `gh` CLI and no stored credential, so a plain `git push` will block. Either
configure GCM and run the push in the background, or ask for a PAT.

**Second quirk:** `git fetch` after the push printed
`* [new branch] main -> origin/main`, but `refs/remotes/origin/main` did not
exist afterwards — `git update-ref` reported success yet wrote nothing, and
`git status` showed `main...origin/main [gone]`. Cause: the directory
`.git/refs/remotes/origin/` did not exist and the nested directory was not being
created. Fix:

```
mkdir -p .git/refs/remotes/origin
printf '%s\n' "$(git rev-parse HEAD)" > .git/refs/remotes/origin/main
```

After that `git status` reads a clean `## main...origin/main`. Re-running the
fetch does **not** fix this — do not rely on that.
